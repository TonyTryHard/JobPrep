## Design decisions: state each one in the plan with your default and reason

Defaults are suggestions; I confirm them when I approve.
- **Q1. Which interviews show.** Default: all except `cancelled`; past ones drawn dimmed; outcome shown in the subtitle.
- **Q2. Follow-up semantics.** An application has one `next_action` + date. Default: one follow-up item per application with a `next_action_date` whose status is not closed (rejected, withdrawn, ghosted, accepted); wishlist is included. "+ Follow-up" asks for the application and the action text, sets the selected date as `next_action_date`, and asks for confirmation before replacing an existing next action.
- **Q3. Study targets.** Topics with a target date and a status other than done. The Study page arrives in M4, so clicking such an item does nothing yet and shows the tooltip "Opens in M4".
- **Q4. `AgendaItem` and color.** Keep `QColor` out of `domain`: the item carries its kind and the UI maps kind to a `Tokens` color. If you deviate from the SPEC field list, record it in the SPEC changelog.
- **Q5. Ordering and day assignment.** An interview belongs to the day of its start only (no multi-day spans). Order inside a day: interviews by time, then follow-ups, then study targets, ties by title.
- **Q6. Status side effects.** Creating an interview does not change the application status automatically. Mention it as a future option only.
- **Q7. Layer toggles.** Remembered between launches through `SettingsService` (default: all three on).
- **Q8. Clicking an agenda item.** Interview → `InterviewDialog` (edit); follow-up → `ApplicationDialog` on the Overview tab; study target → see Q3.
- **Q9. Transactions.** Dialogs that touch more than one repository use one outer `Database::Transaction`, so each repository emits `changed()` once per commit.
