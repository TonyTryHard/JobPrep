## Facts from the fourth GitHub Actions run (Qt 6.8.2; raw logs exist, do not re-derive)

**Ubuntu (CI font set: `fonts-dejavu-core`) is red: 32 of 34 pass, 2 fail, both new from D2:**
- `tst_UiSmoke::testWindowMinimumSizeExceedsLayoutMinimum`: `window minimumWidth (1000) < layout minimumWidth (1015)`.
- `tst_HiDpi::testPagesHiDpi`: 6 violations, **all only at the minimum window size 1000x540**, Light and Dark: `ChipBarChip` width 67 < minimumSizeHint 73 (page 1); `CalendarMonthTitle` width 171 < 186 and 'November 2026' advance 169 > contentsRect 167 (page 3).
Both have one cause: the layout's real minimum width depends on the font (982 on the developer's machine, 1015 with DejaVu on CI), but `MainWindow` hard-codes `setMinimumSize(1000, 540)` (my instruction in D2 E6 was wrong: no constant width is right on every font). With a window narrower than the layout minimum, everything is squeezed and clipped. The tests found a real product problem. On Windows both tests pass (its font gives a smaller layout minimum).

**Windows is down from 13 to 6 failures.** The font directory, the resource initialisation and the two portable tests worked (ui_smoke, all `tst_Page*` except settings persistence, `tst_AgendaListModel`, `tst_Shortcuts`, `tst_HiDpi`, `widgetAt` all pass). Remaining, with the CI-DIAG evidence:
1. **Default `QSettings` is unusable on Windows when no organization name is set.** Evidence (same in `tst_TopicListModel`, `tst_Notifiers`, `tst_StudyRegression`): `org: <empty> app: tst_X fileName: <empty> format: 0 status: 1 writable: false`. Status 1 is `AccessError`; every write is dropped and every read returns the default. Failing: `tst_TopicListModel::settingsKeysAndFallbacks`, `tst_Notifiers::coordinatorEndToEndSettingsLeadMinutesChangeTakesEffect`, `tst_StudyRegression::testChecklistStartupContrastDarkAndLight`. The product is not affected (`main.cpp` sets organization and application name before any `QSettings`). Also note: on Linux the same tests silently write to the developer's real `~/.config/Unknown Organization/<test>.conf`; on Windows the native format would be the registry. Tests must not touch either.
2. **`QTemporaryFile` + `QSettings(path, IniFormat)` writes nothing on Windows.** Evidence: after the first `QSettings` is destroyed the file exists with `size: 0` (organization and application names were set in `tst_PageSettings`, status 0, writable true). Failing: `tst_SettingsService::testTrayHintShownKey`, `tst_SettingsService::testWeeklyGoalSurvivesRestart`, `tst_PageSettings::testWeeklyGoalPersistence`. Likely cause (not proven): the `QTemporaryFile` object keeps the file so that `QSaveFile` cannot replace it. The standard pattern is a `QTemporaryDir` and a settings file path inside it that `QSettings` creates itself.
3. **A Linux-only path in a test.** `tst_ImportExport::testIcsExportFormatDetails` (line 316): `QFile f(u"/tmp/throwaway_sample.ics"_s); QVERIFY(f.open(QIODevice::WriteOnly))` fails on Windows (no `\tmp` there). Under ctest it failed (`33 passed, 1 failed`); the standalone run in the diagnostic step passed, so do not trust that run for this test.
4. My diagnostic step v2 filtered out every `INFO`/`QINFO` line, which removed the `CI-DIAG` lines from the standalone runs (the ctest output still had them). That was my instruction's flaw.
