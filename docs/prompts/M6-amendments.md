## Report rules (strict, same as M4/M5, plus two)
1. Every command output is raw, copied from a real run, with the exact command above it. No `...` placeholders in commands or output, no trimmed output.
2. No line numbers as evidence (`grep -n <symbol>` output, `ls` and test slot names are fine). Hashes only from `git log --oneline`; report written last and committed separately.
3. Totals by command and the arithmetic must hold: baseline 25 binaries, 324 functions.
4. Environment line from commands (`lsb_release -d`, `uname -r`, `g++ --version | head -1`, QtTest `Config:` line).
5. **The M6 plan had pre-flight rows without raw output** (CMake/MSVC flags, `.github` and `RUNNING.md`, shortcut bindings, `QStandardPaths`, `src/platform`/`Q_OS_*`, `reminders_sent`, scripts, test counts and the `wc -l` of `ui_smoke`; one command contained `...`). Part A touches most of them: put the raw output into the Part A report.
6. Never claim Windows works. Say what is read-only reasoning and what is verified by running.

## What is accepted in the plan
Environment line, the pre-flight list, the `reminders_sent` wipe on restore, preserving ids, the automatic safety backup (last 5 files), `QSaveFile`, the CRLF/folding/escaping intent for ICS, close-to-tray disabled with a tooltip, the part split, the SPEC numbering. **A3. Windows code audit (reading plus GCC proxies, no Windows claims).**

- **MSVC `/W4` with `/WX` fails on things GCC `-Wall -Wextra` does not report.** Do a one-off local build in a separate build directory (not committed, not in `build/dev-linux`) with extra flags `-Wshadow -Wconversion -Wsign-conversion` on **our code only** (not Qt headers) and use the result as a proxy for MSVC C4456/C4457/C4458 (shadowing), C4244/C4267 (narrowing, `size_t` to `int`) and C4389/C4018 (sign mismatch). Report the number of warnings per file, fix them in `src/` where the fix is trivial and safe (explicit casts, renamed shadowing variables, `qsizetype`), and list what is left. **A4. `QSignalBlocker` re-audit (the plan's verdicts are wrong for selection models).**
The plan says "no blocker targets a `QAbstractItemModel`, all safe". The M5 checklist bug was a blocker on a model; the same class of bug also exists for **selection models**: `QAbstractItemView` is a *receiver* of `QItemSelectionModel::selectionChanged/currentChanged` (it repaints and scrolls through them), so blocking the selection model's signals stops the view from repainting. That was root cause 2 of the M5 regression (stale outlines) and was patched with a manual `viewport()->update()`.
- Re-audit `TopicBoardColumn.cpp` (selection model) and `StudyPage.cpp` (selection model): verdict **risky**, not safe. For each, show that a repaint/`update()` follows the blocked section and that a **painted** test covers it (`testBoardSelectionPaintedOutlinesBothThemes` covers the board; say which test covers the `StudyPage` one, or add it).
- Rule for the report (proposal for `AGENTS.md`, do not edit `AGENTS.md` yourself): "never block signals of a model or a selection model; block the widget's own signals only; if a selection model must be quiet, use a re-entrancy flag instead".
- Also check `QComboBox`/`QLineEdit` blockers for the case where a view or another widget listens to them for painting (none expected).

**A5. Real key-event test infrastructure (moved up from Part D).**
- A helper in the UI test library that sends a key sequence to the **focused widget of a shown and active window** (`QTest::qWaitForWindowActive`, `QTest::keyClick(focusWidget, ...)`), so `QAction`/`QShortcut` contexts behave like in the real app. Verify on this machine that shortcuts really fire under the offscreen platform; if they do not, find out why and what is needed (window activation, shortcut context) and report it. Do not fake it by calling the action.
- Prove the helper with two tests: Ctrl+1..4 page switching and Ctrl+, (Settings). The full shortcut list stays in Part D.

**A6. Optional proposal (do not implement): shared bootstrap.** The M5 regression tests had to rebuild the composition of `main.cpp` by hand. Describe in the report whether extracting that composition into one function used by both `main.cpp` and the tests (for example `src/app/Bootstrap`) is cheap, and what it would risk. ## Part C amendments (binding, implemented later)
- **C1. Threading (the plan's biggest gap).** A `QSqlDatabase` connection must only be used in the thread that created it. The worker opens **its own connection** (unique name, same file, WAL, busy timeout) and removes it when done; it never touches the app's repositories or main connection. Add a small `Database` helper for this. While a restore runs, `ReminderService` is paused and the dashboard refresh is deferred (or tolerates `SQLITE_BUSY`; say which). After the commit one `dataReplaced` event makes every repository emit `changed()` once (coalesced refresh), the Study selection and open panels reset safely, and the progress dialog closes. In-memory test databases cannot be shared between connections: restore and backup tests use a **temp file** database. Test that the GUI event loop keeps running during a restore (a timer ticks).
- **C2. Foreign keys.** Do not "disable foreign key checks if needed": `PRAGMA foreign_keys` is a no-op inside a transaction. Keep it ON; delete children before parents and insert parents before children (tracks, topics, subtasks, sessions, applications, status history, interviews), or use `PRAGMA defer_foreign_keys=ON` inside the transaction. Test sessions with a null `topic_id`.
- **C3. Validation and results.** Validate before touching the DB: format, version (unknown version rejected, unknown extra fields ignored), types, enum strings, date formats, unique and positive ids, referential integrity, size limit. Services return a result with an error kind and context, **no presentation text**; the UI maps it to messages. Tests: wrong format, wrong version, truncated JSON, empty file, bad enum, broken reference, duplicate id: DB untouched (compare all tables).
- **C4. Consistent snapshot.** Backup reads inside one read transaction.
- **C5. ICS must be importable.** RFC 5545 requires more than the plan lists: `BEGIN:VCALENDAR`, `VERSION:2.0`, `PRODID`, `CALSCALE:GREGORIAN`; per event `UID` (stable, for example `jobprep-interview-<id>@jobprep.local`), `DTSTAMP` (UTC `Z`, injected clock), `DTSTART`, `DTEND` (start + duration), `SUMMARY` ("Interview: <company> — <type>"), `LOCATION`, `DESCRIPTION`, and `VALARM` with `ACTION:DISPLAY`, `DESCRIPTION`, `TRIGGER:-PT60M`. Local times stay floating (SPEC §10). Cancelled interviews are not exported (state in §14). Fold at 75 **octets** and never split a UTF-8 sequence; escape `\`, `;`, `,` and newlines. Open the file **without** `QIODevice::Text` and write `\r\n` explicitly (also for CSV, which keeps its BOM). Byte-level tests with Cyrillic text and an emoji, a 200-character line, a comma/semicolon/newline in notes.
- **C6. Safety backup.** `AppDataLocation/backups/pre-restore-<timestamp>.json`, created in the worker before the wipe; if it cannot be created the restore is aborted; keep the last 5 files and delete only files that match this pattern. Test with a read-only folder.
- **C7. Equality test.** A helper that compares every table, every column, including ids and timestamps; a hand-built dataset with arithmetic in comments plus the seed data. Performance sanity: restore of 1,000 applications and 5,000 sessions within a generous bound, time printed with `qInfo`.
- **C8. Data section UI.** `QFileDialog` with default names containing the date; result and errors through message boxes or the existing status mechanism; "Load sample data" only on an empty DB or after confirmation; "Open data folder" through `QDesktopServices::openUrl(QUrl::fromLocalFile(...))` with the result handled. The restore confirmation states that a safety backup is made and where.
