### Item 2 (date keyboard)

- **2a. The proposed implementation is fragile.** It posts a synthesized mouse press at `SC_SpinBoxDown`. Qt itself opens the popup in `QDateTimeEdit::mousePressEvent` when the click hits the **combo-box arrow** (`QStyleOptionComboBox`, `SC_ComboBoxArrow`), and the arrow position differs per style. A rectangle that happens to work in Fusion on offscreen can miss on Windows (`windowsvista`, `windows11`, `windows`). Required before choosing: (1) read in the Qt headers/docs what public API exists to show the popup (there is none expected; say what you found by command); (2) compare the options: synthesized click at the arrow rectangle computed from `QStyleOptionComboBox`/`SC_ComboBoxArrow`; or an own popup (`QCalendarWidget` in a `Qt::Popup` frame positioned under the field, which gives full control and no private API); private Qt headers are **not** allowed. Recommend one and say why.
- **2b. Test across styles.** The key tests run in every style that `QStyleFactory::keys()` offers on that OS (Linux CI: `fusion`, `windows`; Windows CI: also `windowsvista`/`windows11`). Print the style name in the test output. Say what offscreen still cannot prove.
- **2c. Shortcut collisions.** `Alt+Down` may collide with window-level shortcuts or the Study board (`Alt`+arrows). Show `grep -rn "Alt+\|Qt::ALT\|AltModifier" src`. A `QAction`/`QShortcut` shortcut takes priority over `keyPressEvent` unless the widget accepts `QEvent::ShortcutOverride`: handle it for the keys you use, and test it **inside** the real dialogs and the Study detail panel (where the board shortcuts exist), not only on a bare widget.
- **2d. Modifier check.** `modifiers() == Qt::AltModifier` rejects `Alt+Down` from the numeric keypad (`KeypadModifier`). Use `(modifiers() & ~Qt::KeypadModifier) == Qt::AltModifier`.
- **2e. Esc and Enter.** Test that Esc closes **only the popup** and the dialog stays open, a second Esc closes the dialog, and that Enter in the popup selects the date without accepting the dialog.
- **2f. All five controls by name.** The plan promises four dialogs but the slots cover two of them plus a bare widget. Inventory is five controls (`TopicDetailPanel`, `InterviewDialog`, `ApplicationDialog` twice, `SessionDialog`). One parametrised slot per control (data-driven rows named after the control) in a single place, plus the failing-before proof on the current code.
- **2g. Tooltip.** Show how the hint is added without overwriting existing tooltips (validation messages). Say where the hint is translated (it is a new `tr()` string).
