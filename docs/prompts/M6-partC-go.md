**Export commit.**

**Restore commit (C1-C3, C6, C7).**
- Worker thread with **its own connection** (unique connection name, same file, WAL and busy timeout like the main one); the `QSqlDatabase`/`QSqlQuery` objects go out of scope before `QSqlDatabase::removeDatabase` (otherwise Qt warns and the warning gate fails). - Before starting: flush pending Study edits (`flushPendingEdits()`), pause `ReminderService` (add a documented pause/resume; tests: a tick during restore delivers nothing and records nothing), defer or tolerate dashboard refresh. After the commit: one "data replaced" event; every repository emits `changed()` once (the coalesced refresh runs once, test it with the existing refresh counter); the Study selection and the open detail panel reset safely when their topic vanished (existing deleted-topic handling, test it); the progress dialog closes; `reminders_sent` is wiped; app settings (including `sampleDataPrompted`) are not touched (state it in §14).
- Validate **before** touching the DB (C3): format, version (unknown version rejected; unknown extra fields ignored; missing optional fields become NULL; missing required fields are errors), types, enum strings (reuse `domain` enum conversion, do not copy a string table), date and time formats, positive unique ids per table, referential integrity (topics->tracks, subtasks->topics, sessions->topics (null allowed), status history and interviews->applications), size limit (state the number in §14, suggestion 64 MB).
- Foreign keys stay ON (C2): delete children before parents, insert parents before children; or `PRAGMA defer_foreign_keys=ON` inside the transaction. Do not "disable foreign key checks". One transaction; any error rolls back and leaves the DB byte-for-byte unchanged in content (compare all tables).
- Safety backup (C6) in the worker before the wipe: `AppDataLocation/backups/pre-restore-<timestamp>.json`; if it cannot be written the restore is aborted with an error kind; keep the last 5 matching files and delete only files that match the pattern. Test with a read-only folder.
- Explicit ids with AUTOINCREMENT: after a restore, a newly added topic gets an id greater than every restored id (test). Say what happens to `sqlite_sequence` and exclude it from the equality helper with a reason.
